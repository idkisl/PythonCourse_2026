СЕМИНАР 12. SQL И ORM В VK-БОТАХ
============================================================
ЧАСТЬ 1. SQL-ЗАПРОСЫ В SQLITESTUDIO
============================================================

Используйте файл sfscores.sqlite — базу организаций и санитарных проверок Сан-Франциско. Откройте его в SQLiteStudio, изучите структуру таблиц и выполняйте запросы в SQL-редакторе.

Основные таблицы и поля:

businesses — организации:
    business_id — идентификатор организации;
    name — название;
    address — адрес;
    postal_code — почтовый индекс;
    owner_name — название или имя владельца.

inspections — проверки:
    business_id — идентификатор организации;
    Score — балл проверки (может отсутствовать);
    date — дата в формате YYYYMMDD;
    type — тип проверки.

violations — нарушения:
    business_id — идентификатор организации;
    date — дата;
    ViolationTypeID — код вида нарушения;
    risk_category — категория риска (Low Risk, Moderate Risk, High Risk);
    description — описание нарушения.

Связь между таблицами осуществляется по business_id.
У одной организации может быть много проверок и нарушений.
Дата не является уникальным идентификатором проверки.

Образец оформления запроса (не является заданием):
    SELECT name, address
    FROM businesses
    LIMIT 5;

Для каждого задания сохраните отдельный SQL-запрос с комментарием, содержащим номер задания. В запросах на средний балл исключать NULL вручную необязательно: AVG игнорирует NULL. Не заменяйте отсутствующие оценки нулями.

БАЗОВЫЙ УРОВЕНЬ

1. Список организаций.
Выведите названия и адреса всех организаций с почтовым индексом 94104. Отсортируйте их по названию в алфавитном порядке.

2. Низкие баллы.
Выведите идентификатор организации, дату и балл всех проверок, в которых балл меньше 70. Отсортируйте по баллу от меньшего к большему, при равенстве — по дате. Выведите первые 20 строк.

3. Типы проверок.
Выведите все уникальные типы проверок в алфавитном порядке. Отдельным запросом определите их количество.

4. Поиск по названию.
Найдите организации, в названии которых встречается слово Cafe (достаточно поиска подстроки). Выведите название, адрес и владельца.

СРЕДНИЙ УРОВЕНЬ

5. Статистика проверок.
Для каждого типа проверки определите общее количество проверок, количество проверок с известным баллом и средний балл. Округлите средний балл до двух знаков после запятой. Отсортируйте по общему количеству проверок по убыванию.

6. Нарушения по категориям.
Определите количество нарушений каждой категории риска за 2016 год. Выведите категорию и количество, отсортируйте по количеству по убыванию.
Примечание: сначала проверьте формат и тип значения date. Можно использовать substr(CAST(date AS TEXT), 1, 4).

7. Организации и проверки.
Выведите название организации, адрес, дату проверки и балл для всех проверок с баллом ниже 60. Используйте JOIN. Отсортируйте по баллу по возрастанию.

8. Средняя оценка организации.
Для каждой организации, имеющей не менее пяти проверок с известным баллом, определите количество таких проверок и средний балл. Выведите идентификатор, название, количество проверок и средний балл. Покажите 10 организаций с наименьшим средним баллом.
Примечание: используйте JOIN, GROUP BY и HAVING. Группируйте по идентификатору и названию.

ПОВЫШЕННЫЙ УРОВЕНЬ (ДОПОЛНИТЕЛЬНО)

9. Организации без проверок.
Найдите организации, для которых в таблице inspections нет ни одной записи. Выведите идентификатор и название.
Примечание: используйте LEFT JOIN и проверку на NULL в правой таблице либо NOT EXISTS.

10. Проверки хуже среднего.
Найдите проверки, балл которых ниже среднего балла всех проверок в базе. Выведите название организации, дату и балл. Используйте вложенный запрос.

11. Организации с опасными нарушениями.
Для каждой организации определите количество нарушений категории High Risk. Выведите 10 организаций с наибольшим количеством таких нарушений. Организации без нарушений данной категории не выводите.

12*. Сводный отчёт.
Для каждой организации выведите название, число проверок, средний балл и число нарушений категории High Risk. Организации без проверок или нарушений также должны присутствовать. Для отсутствующего среднего балла сохраните NULL, для отсутствующего количества выведите 0.
Примечание: отдельно сгруппируйте inspections и violations по business_id, затем присоедините результаты к businesses. Простое объединение всех трёх исходных таблиц может размножить строки и исказить подсчёты.

============================================================
ЧАСТЬ 2. ORM В VK-БОТАХ
============================================================

Проект: VK-бот «Мои задачи».

Бот позволяет пользователю создавать личный список задач, просматривать его и отмечать задачи выполненными. Данные должны сохраняться после перезапуска программы. Каждый пользователь имеет доступ только к собственным задачам.

Используйте ранее изученные vk_api, VkBotLongPoll, обработку MESSAGE_NEW и SQLAlchemy ORM. Можно взять за основу ранее написанного VK-бота. Для установки зависимостей:
    python -m pip install vk_api sqlalchemy

Не храните токен сообщества в базе или в отправляемом преподавателю коде. Используйте переменную окружения либо локальный PERSONAL_DATA.py, исключённый из сдачи.

ЗАДАНИЕ 1. Подготовка проекта и моделей

Рекомендуемая структура (допускается сначала реализовать всё в одном файле):
    main.py
    data/
        __init__.py
        db_sessions.py
        __all_models.py
        user.py
        task.py
    db/
        tasks.db

Модель User (таблица users):
    id — Integer, первичный ключ;
    vk_id — Integer или BigInteger, уникальное обязательное поле;
    tasks — relationship с моделью Task.

Модель Task (таблица tasks):
    id — Integer, первичный ключ;
    user_id — Integer, внешний ключ users.id, обязательное поле;
    text — String или Text, обязательное поле;
    is_done — Boolean, по умолчанию False, обязательное поле;
    user — relationship с моделью User.

Связь User — Task: один ко многим. Настройте back_populates с обеих сторон.
При первом запуске должны автоматически создаваться обе таблицы.

ЗАДАНИЕ 2. Регистрация пользователя

При получении сообщения определите VK ID отправителя через event.object.message['from_id']. Не используйте peer_id в качестве идентификатора владельца данных: в беседе peer_id относится ко всей беседе.

Найдите пользователя в таблице users по vk_id. Если такого пользователя нет, создайте его и сохраните изменения. Повторное сообщение не должно создавать нового пользователя.

Команда: старт
Ответ: Привет! Я бот для хранения задач. Напиши «помощь».

Команда: помощь
Ответ: список доступных команд с примерами.

ЗАДАНИЕ 3. Добавление задачи

Команда: добавить Подготовить доклад

Бот должен выделить текст после команды, создать объект Task, связать его с текущим пользователем и сохранить через ORM. Пустой текст не допускается.

Пример ответа: Задача №1 добавлена.
Номер задачи — её настоящий id в базе; номера могут отличаться от примеров.
Не переводите весь текст сообщения в нижний регистр: это изменит содержание задачи.

ЗАДАНИЕ 4. Просмотр задач

Команда: задачи

Выведите только задачи текущего пользователя в порядке id. Покажите номер, статус и текст.

Пример:
    1. [ ] Подготовить доклад
    3. [x] Решить задачи по SQL

Если задач нет, сообщите об этом.
Используйте relationship или select(Task) с фильтрацией по user_id.

ЗАДАНИЕ 5. Выполнение задачи

Команда: выполнить 1

Найдите задачу по id И идентификатору текущего пользователя. Измените is_done на True и сохраните изменения. Если номер некорректен, задача отсутствует или принадлежит другому пользователю, сообщите, что задача не найдена либо номер некорректен. Повторное выполнение не должно приводить к ошибке.

Примечание: поиск только по id недостаточен — другой пользователь может угадать номер чужой задачи.

ЗАДАНИЕ 6. Удаление задачи (дополнительно)

Команда: удалить 1
Удалите только собственную задачу пользователя с указанным id. Используйте session.delete() и session.commit().

ЗАДАНИЕ 7. Статистика (дополнительно)

Команда: статистика
Выведите общее число задач пользователя, число выполненных и число невыполненных задач. При желании используйте SQLAlchemy func.count вместо подсчёта объектов в Python.

ЗАДАНИЕ 8*. Кнопки и состояния диалога (дополнительно)

Добавьте клавиатуру VK с кнопками «Добавить», «Задачи», «Помощь». При нажатии «Добавить» бот запрашивает текст задачи следующим сообщением. Храните состояние диалога отдельно для каждого пользователя (например, в дополнительном поле модели User). После сохранения задачи сбрасывайте состояние. Команда «отмена» должна отменять ввод.

ОБЩИЕ ТРЕБОВАНИЯ К БОТУ

1. Работайте через ORM, не через ручные SQL-запросы.
2. Используйте select(), where(), session.scalars(), session.add(), session.commit() и relationship по назначению.
3. Создавайте сессию на обработку сообщения; закрывайте её после обработки. Удобно использовать with db_sessions.create_session() as session:.
4. При ошибке записи выполняйте rollback; не оставляйте сессию в ошибочном состоянии. Обрабатывайте неправильный ввод без остановки бота.
5. Сначала зафиксируйте изменения в базе, затем отправьте сообщение об успешной операции.
6. В целях приватности бот должен обслуживать команды с личными данными только в личных сообщениях сообщества; в групповой беседе предложите перейти в личные сообщения.
7. Токены и другие секреты не должны попадать в сдаваемые материалы.
