СЕМИНАР 11
Тема: VK-боты



1. ОБЩЕЕ ОПИСАНИЕ

Разработайте VK-бота с текстовым квестом. Игрок проходит несколько связанных
сцен, а его выбор изменяет дальнейший сюжет и/или характеристики персонажа.


2. ПОДГОТОВКА ПРОЕКТА

2.1. Создайте или используйте учебное сообщество VK с включёнными сообщениями.
2.2. Включите Bots Long Poll API и событие message_new.
2.3. Установите пакет vk_api.
2.4. Создайте файл quest_vk.py. VK_TOKEN и GROUP_ID возьмите из PERSONAL_DATA.py.
2.5. Не публикуйте токен и не прикладывайте PERSONAL_DATA.py к сдаваемой работе.


3. ОСНОВНЫЕ ФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ

3.1. Команды бота

Реализуйте команды:

  начать   — начало игры. Новому игроку предлагается зарегистрироваться.
             Зарегистрированному показывается текущая сцена и доступные действия.
  помощь   — краткое описание игры и перечень команд.
  статус   — имя игрока, текущая сцена, очки и инвентарь.
  сброс    — удаление игрового прогресса только текущего игрока;
             после подтверждения можно начать заново.
  меню     — показать основное меню с кнопками.
  выход    — скрыть клавиатуру и завершить текущий диалоговый сценарий,
             НЕ останавливая программу и работу других пользователей.

Команды должны работать без учёта регистра и лишних пробелов.
Команда «помощь» должна быть доступна на любом этапе квеста.

3.2. Регистрация и игровые данные

При первом «начать» бот спрашивает имя или никнейм игрока.
После получения непустого имени создайте запись игрока.

Для каждого игрока храните как минимум:
  user_id       — VK ID отправителя (from_id);
  user_name     — имя, выбранное игроком;
  state         — этап диалога: регистрация / игра / подтверждение сброса;
  current_scene — код текущей сцены;
  inventory     — список полученных предметов;
  points        — число игровых очков.

Пример структуры (значения условные):

  players = {
      123456: {
          "user_name": "Алекс",
          "state": "playing",
          "current_scene": "forest",
          "inventory": ["ключ"],
          "points": 10
      }
  }

Состояния разных игроков не должны смешиваться. Для личных сообщений достаточно
ключа from_id. Если игра работает в групповых беседах, предусмотрите независимые
сессии (например, используйте составной ключ из peer_id и from_id).

3.3. Сюжет и сцены

Придумайте собственный сюжет минимум из ТРЁХ связанных сцен.
В каждой сцене должны быть:
  - описание обстановки (не менее двух предложений);
  - ситуация, требующая выбора;
  - минимум два возможных действия;
  - результат действия: переход в другую сцену и/или изменение характеристик.

Обязательно предусмотрите как минимум:
  - одно сюжетное разветвление;
  - один предмет, который можно получить;
  - одно действие, меняющее points;
  - одну проверку условия (например, пройти дверь можно только с ключом);
  - хотя бы один достижимый финал.

Пример-направление (не обязательно повторять):
  Старт: развилка — пойти в лес или к реке.
  Лес: найден сундук — открыть или обойти.
  Река: мост — перейти или искать обход.

3.4. Клавиатуры VK

Главное меню реализуйте обычной клавиатурой VkKeyboard(one_time=False).
Добавьте кнопки «Начать», «Статус», «Помощь», «Выход» и распределите их
по строкам с помощью add_line(). Используйте осмысленные цвета кнопок.

Как минимум в одной сцене используйте inline-клавиатуру
VkKeyboard(inline=True) с текстовыми кнопками и payload.

Пример смысловой схемы (не готовое решение):
  название кнопки: «Пойти в лес»
  payload: {"action": "go_forest"}

При нажатии текстовой кнопки бот получает MESSAGE_NEW. Считайте payload
из message.get("payload") и при наличии разберите JSON. Не используйте только
название кнопки, если в ней предусмотрен payload. Неверный/отсутствующий payload
не должен аварийно завершать программу.

При переходе между сценами отправляйте новую клавиатуру с действиями,
относящимися к текущей сцене.

3.5. Состояния диалога

Используйте состояния минимум для регистрации, прохождения квеста и
подтверждения сброса. Проверяйте корректность ответа перед переходом
к следующему состоянию.

Если пользователь ввёл посторонний текст, бот должен объяснить доступные
действия, не изменяя сцену и не теряя прогресс.


4. СОХРАНЕНИЕ ПРОГРЕССА

Сделайте сохранение словаря игроков в JSON-файл players.json и загрузку при старте.
После остановки и нового запуска бота команда «начать» должна открывать
последнюю сохранённую сцену зарегистрированного игрока.

В JSON ключи объектов строковые: при чтении при необходимости преобразуйте
их обратно в числа. Не сохраняйте токен вместе с данными игроков.

Если работа выполняется в рамках одного семинара, сначала обеспечьте корректное
хранение в оперативной памяти, затем добавьте JSON как завершающий этап.


5. ОРГАНИЗАЦИЯ КОДА

Рекомендуется выделить функции:
  send_message(peer_id, text, keyboard=None)
  get_player(user_id)
  process_message(user_id, text, payload=None)
  show_scene(...)
  save_players()
  load_players()

Названия функций могут отличаться. Главное — не размещать всю логику квеста
в одном длинном цикле обработки событий.
